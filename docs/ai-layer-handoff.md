## 一、项目背景（30 秒版）

开源 Android 虚拟人 SDK + Demo：Filament(C++/JNI) 渲染底座 + 纯客户端（Serverless）AI 对话——Android 端直连公网 OpenAI 兼容 API（LLM + TTS），端侧口型解算与生理微动作，支持酒馆人物卡（SillyTavern Character Card）。

四层 Gradle 架构（依赖只能向下）：

```
:app (demo)  →  :avatar-orchestrator (业务中台)  →  :avatar-ai-adapter (能力适配)
                        └──────────────→  :corelib (渲染底座,已存在)  ←──┘ (严禁 adapter→corelib)
```

对齐参照物：**AIRI**（moeru-ai/airi）本地源码在 `/home/neethu/projects/airi`，其关键 file:line 锚点与对齐参数已固化在项目记忆 `airi-source-anchors` 中（新会话自动加载 MEMORY.md 索引，需要细节时读该记忆文件）。

## 三、关键设计决策（改代码前必读）

1. **口型走离线时间线，不做实时 tap**：TTS 解码后一次性 `analyze()` 出时间线，播放时按 AudioTrack 时钟采样 + VowelDriver 状态机逐帧平滑。比 AIRI 的 AudioWorklet 实时分析更稳、无黑盒依赖。若要改口型手感，调 `VowelDriver` 常量区。
2. **FaceDriver 独占全部缓动**：corelib `VrmExpressionManager` 语义是「setExpression 写目标权重 + 内部按 transitionDuration lerp + 多表情按 bind 加法累加 clamp」。FaceDriver 启动时 `setExpressionTransitionDuration(0)` 切瞬时模式，自己画所有曲线——对齐 three-vrm 每帧 `setValue` 语义。**不要**在 corelib 里再加缓动。
3. **VRM 表情名→morph 走模型自带的 expressionMap**（corelib 已解析 VRM1.0 preset+custom / 0.x blendShapeGroups），FaceDriver 按 `getAvailableExpressions()` 门控发送，缺名字自动跳过，**禁止硬编码 aa→jawOpen 之类映射**。corelib 解析时会对每个表达式的绑定权重做归一化（最强 bind 缩放到 1.0，比率保持，见 A.1 第 16 条），使"表达式权重 1.0 = 主 morph 满幅"跨模型语义一致。
4. **情绪协议是自定的** `<|emotion:name:intensity|>`，由 SystemPromptAssembler 注入指令教模型使用；可情绪集 = EmotionBlender.defs 的 7 个键。
5. **adapter 的 okhttp/serialization/coroutines 必须 `api()`** 不能 `implementation`——构造器默认参数把 OkHttpClient/JsonObject 泄进了公共签名，改 implementation 会编译失败。
6. TTS response_format 固定 `"wav"`（AiChat.kt），换 provider 若报 400 需要把格式做成设置项。

## 四、已知坑清单（每条都真实踩过）

1. AIRI 的 profile.json 有 **12 个音素条目且重名**（A/I/U/E/O/S 各两套录音）：打分按 12 条目归一化，`VowelDriver.setPhonemeGroups` 按名分组 max 合并，S 视作 ih 别名。
2. profile 里 `useStandardization` 是 JSON 布尔，**不能** `jsonPrimitive.int` 解析（直接抛 NumberFormatException）。
3. `VowelDriver.lastActiveTime` 必须初始化 0 不能 NEG_INF——t=0 时 `t-last=∞` 会让首帧起永远静音（AIRI 时钟从 0 起）。
4. 情绪标记强度正则要带 `-?`（负号），否则 `<|emotion:sad:-2|>` 整体不匹配、原文穿透进语音。
5. kotlin-jvm 插件在混 AGP 工程必须在 root `build.gradle.kts` `apply false` 声明，否则 "already on the classpath with an unknown version"。
6. wLipSync C 版 `downSample` 的 `i1=min(i0,size-1)` 是上游笔误（插值失效），Kotlin 版已改成 `i0+1`，勿"改回去"。
7. wLipSync `low_pass_filter` 是把滤波项**加在原始数据上**的半边对称卷积（ quirky 但标定数据就是这么采的）——Dsp 移植保持原样，别"修正"。
8. Compose UI 在 MIUI 上 uiautomator 只能看到部分节点（TextField 不可见）：真机冒烟走 `run-as` 直接写 prefs（先 force-stop）+ 截图(1:1 物理分辨率) + bounds 中心 tap。
9. corelib 的 `AvatarState`（渲染状态）与 orchestrator 的 `ConversationPhase`（会话状态）是两套，别混。
10. **filament MaterialInstance 设置未声明的 uniform 是 precondition abort（SIGABRT 闪退）**：MToonApplier 首版把 lightDirection 设到 hidden 材质实例上直接杀进程——hidden 实例单独列表管理，不发光照参数。
11. **filament 纹理上传的像素缓冲要下一帧 beginFrame 才消费**：一次 loadImage 循环里传 20+ 张 2K 纹理，所有 allocateDirect 像素缓冲同时存活顶爆 256MB Java 堆（真机 OOM）——每张 `tex.setImage+generateMipmaps` 后 `engine.flushAndWait()` 逐张排空。
12. **MIUI 真机 `adb shell input tap` 可能被吞（swipe 正常）**：设置页点选项用 `input swipe x y x y-1 200` 模拟点击仍可能无效，可靠的程序化入口走 `ai_cmd`（如 render_mode）。
13. **filament `Engine.destroyMaterialInstance` 在实例仍被任何活着的 renderable 引用时 precondition abort（SIGABRT）**：MToon 下切角色必崩的根因——`loadModelBytes` 原顺序是先 `mtoonApplier.destroy()`（旧实例还挂在旧资产的 renderable 上）后 `loadModelGlb`（内部才 destroyModel）。abort message 形如 `destroying MaterialInstance "MToonSurface" which is still in use by Renderable (entity=351, instance=2, index=0)`。修=重载/onDestroy 都是**先 `modelViewer.destroyModel()`（摘掉持实例的 renderable）再 destroy applier**；只有旧模型也是 MToon（applier 非空）的切换才触发，所以是"经常"而非"必现"。纹理没有同款 in-use 扫描，实例先于纹理销毁的顺序别再反过来。
14. **帧率测量两个假象**：①`dumpsys gfxinfo` 对本应用永远 0~5 帧——Filament 直渲 SurfaceView 自持 EGL context,完全绕过 gfxinfo 统计的 HWUI 管线;测帧率只能用应用自身的 fps 统计（`ai_cmd state` 的 fps= 字段,500ms 窗口均值）。②MIUI 锁屏/灭屏时 renderer 走 onPause 停帧,但主线程 `ai_cmd` 照样响应、FaceDriver 的 Choreographer 回调照跑——锁屏下测到 fps=0 先解锁再下结论。
15. **VRM 0.x 与 1.0 的表情 preset 名不同表**：0.x 元音是单字母 `a/i/u/e/o`、分侧眨眼是 `blink_l/blink_r`，1.0 是 `aa/ih/ou/ee/oh`、`blinkLeft/blinkRight`；SDK 全链路只说 1.0 名。corelib `VrmExpressionManager.parseExpressions` 已做归一 + `joy/sorrow/fun`→`happy/sad/relaxed` 的缺位别名（见第二节 2026-10-10 条目），排查表情问题时先看 `ai_cmd list expressions` 的实际名字集合，别假设模型名=协议名。
16. **三类标签的正则形状不对称，排查「标签被朗读」先查形状再查名字**：emo 一直允许 `:强度` 段而 act/cam 原本只认单段——模型会把 `<emo:名:强度>` 的习惯带进 `<act:laugh:0.5>`，形状不匹配整段透传进 TTS（2026-10-11 已修，act/cam 同款容忍强度段）。未知名（形状对但词表外）会被过滤不朗读，但要知道模型写了什么得看 UnknownTag 事件（聊天面板灰字 / `[InfoStreamDectect] UnknownTag` 日志）——别再猜「它到底发了什么标签」。
17. **流式 tool_calls 的后续分片 id/name 有两种缺失形态**（2026-10-11 实测，docs/agent-provider-matrix.md）：硅基流动显式发 `"id":null,"name":""`，火山/OpenRouter 直接省略字段——累积器必须把 null 与空串**都**当缺失，只在非空时覆写；且 `finish_reason` 不可作工具轮判据（`Finish.toolCalls` 非空才算），测试 fake 的 ScriptedLlm 记录请求必须存 `messages.toList()` 快照（工具循环就地扩展 messages，按引用存会被后续轮改写）。
18. **`SkillHost.nowMs()` 是开机单调时长（elapsedRealtime）不是墙钟**：`get_device_time` 工具因此直用 System.currentTimeMillis；凡「当前时间」语义一律别走 SkillHost 那根缝。
19. **VRMA 播放的「绝对 elapsed 采样」在变速下跳相位**（自由走动 P0 修掉）：`update(elapsed)` 直接拿渲染时钟采样，timeScale 只能乘整段 elapsed——中途变速（走动步态 timeScale=速度/基准速度）会让相位瞬跳。已重构为 playhead 积分（帧间 dt×speed，`update` 不被调用=自然暂停），**后续任何「播放速度可变」的需求都必须走 playhead，别回退到乘 elapsed**。
20. **VRM0/VRM1 的朝向差异止步于 root 矩阵，世界系旋转/位移直接在 root 上做**：0.x 的 Y-180 翻转烘在 root 矩阵 3×3 块内，转向=3×3 块左乘 Ry(θ)（平移列不动，顺带保住 transformToUnitCube 的缩放）、位移=平移列累加，两代模型同一套代码。**别**在 hips 局部系做移动——hips 局部 X 在 0.x 是翻转的（拖拽累加时的 sign 补丁同源），且动画每帧覆写会冲掉。
21. **纯数学类（LocomotionEngine/HipsDragOffsetSolver/PoseMimicSolver 一族）不带 android.util.Log**——JVM 单测没有 mock，`Log.i` 直接 RuntimeException "not mocked"；日志放调用方渲染器层。同理 app 层要进单测的 JSON 解析用 kotlinx.serialization，别用 org.json（not-mocked 桩）。
22. **跟随类运镜的目标姿态不许每帧从当前相机状态重取（自参照固化漂移）**：FOLLOW 首版每帧从当前 gaze 取 yaw/pitch，一旦漂移就把自己固化为新目标（真机收成低机位仰拍贴身特写）——修=激活瞬间快照一次（`followYawPitch` 字段）。同理「跟拍距离」不能取比当前机位近的固定值（2.8×span<初始 5m，相机会先拉近穿越再跟），要 max(当前距离, 下限)。
23. **过渡素材（状态过渡系）大多带 root motion，接进走动前必须测 hips 平移**（P1 实测：`Twist Left Idle To Walk 180` 系带 0.8~1.7m 前向位移，与程序位移叠加=双重位移+播完回弹；`Female Walk Forward To Twist Left Idle` 6cm≈干净可用）。测量方法=walk-calib 的 FK 直接采样 hips translation 通道的 XZ 范围（一段 node 脚本）。机制侧已备好 `setWalkTransitions`（起步 hold 冻结程序位移），但**默认关**，真机 A/B 过眼验再定默认；one-shot 过渡剪辑播完由引擎自动接管 idle，不需要手写切换。
24. **阻塞等待"到达"的语义进不了 move_to 工具**：ToolRegistry 超时默认 10s，正常步速走 2m+ 必超时——工具失败结果回灌等于给模型埋必炸雷。定式=**异步起步**（起步即返回确认文案，模型继续说话），到达走 `WalkArrived` 事件给 UI（`AvatarController.walkFinished` 流是 corelib→orchestrator 事件的桥，tryEmit+DROP_OLDEST）。
25. **资产名约定函数要对照 assets 目录树测**：`sceneMetaAssetName("home.glb")` 返回 `home.meta.json`（缺 `scene/` 前缀）单测照样绿——测试只锁了函数自身口径没锁真实路径，FileNotFound 又被 runCatching 吞掉，**meta/bounds 在真机静默失效一整个 P0 周期**（症状：walk_state 显示 `placement: none`）。凡「assets 路径拼接」类函数，测试断言必须写全 `scene/xxx` 形态。
26. **模型会把工具调用当文本吐**（P0.5 doubao set_ambience 形态的走动版）：DeepSeek 对走动请求 3 走 1 成，失败时吐 `<move_to carpet>`/`<move_to anchor="desk">` 伪工具调用或 `<move:window→carpet>` 发明形状，整段进 TTS 朗读且动作不发生。SDK 兜底=提取器按形状抑制+上报（snake_case 名含下划线判工具形态，命名空间宽容回退接离谱名字），**不执行**——文本不是工具通道，执行它等于绕过原生协议；正经修复在 provider 侧（required 重试/模板解析扩展，P0.5 已定档）。抑制正则的误伤防线=要求名字含下划线（散文 `<see this>`/`<hello>` 永不命中）。
27. **自愈/超时类状态机必须有真实触发口，别只造机器**：`VrmPoseMimicEngine` 的还原机器（缓动/清账/回 idle）齐备、注释也写了「断供>600ms 自愈还原」，但全仓库没有一处把 `restoring` 置 true——断供后 `engaged` 永久 true，下游互斥（locomotion MIMIC_ACTIVE）被无限期卡死。P1 真机验收由走动互斥测试探出。审查方法：grep 状态标志的全部赋值点，**只有读没有写的布尔=死机器**。
