# 4v4 辩论赛 P0 模拟器验证记录

日期：2026-10-18。关联设计：[可行性与实施方案](debate-feasibility.md)。本轮使用固定稿和真实 TTS 验证 P0，保留九个独立角色复用三个内置 VRM 的配置。

## 本轮修复

- 移除 `app/src/main/assets/debate/chair.glb`，内建布局和 DTO 默认关闭独立座椅。按本轮要求暂缓椅子尺寸、朝向及座面承托验收。
- 双方由各两排改为左右各一排四席；正方在画面左侧，反方在右侧，主持人位于中后方。辩手间距 0.72，双方内侧间距 1.4，朝中线偏转 12°。
- 修正 `AvatarSpawn` 偏移与布局世界深度混用：模型归一化已经位于 Z=-4，不能再把座位世界 Z 直接叠加，否则人物会被放到场景后方。
- 将加载限流移到实际 `loadAvatar` 调用前后，逐个等待 Ready/Error；原来的 Semaphore 只包裹等待结果，没有限制九个加载任务同时启动。
- 起立素材长约 4.83 秒，原速超过短赛程 4 秒的姿态准备上限。坐站过渡改为 2 倍速；动作加载失败不再伪报站立成功；姿态超时也不会直接重试音频绕过站稳门控。
- 姿态完成通知绑定发起时的 epoch/turnId；重载时取消旧事件和姿态订阅，避免旧通知推进新比赛或订阅累积。
- 暂停起立后恢复仍等待姿态完成；手动结束发言先取消旧音频再交接；跳段时收起上一段站姿。
- 正常换攻辩轮和离开攻辩阶段时取消旧轮计时器，避免提前结束的上一轮在下一轮起立时误触发墙钟截止。正常墙钟耗尽不再残留为界面错误。
- 语音用时从首段音频实际起播计算，不包含 TTS 准备；TTS 失败、无音频起播不再记为成功播放。
- 舞台为顶部赛况、底部按钮和右侧人员牌预留空间，避开系统栏；比赛页面保持亮屏。加载完成和比赛空闲时自动取九人全景；单人镜头按头胸边界拟合，保留头顶余量。
- 冷启动 Intent 的 load 命令等待舞台挂载；RUNNING 状态下的重载在拆除舞台前拒绝。

## 自动化回归

```bash
./gradlew :app:assembleDebug :corelib:testDebugUnitTest :avatar-orchestrator:testDebugUnitTest
```

已分别完成构建及两个模块的全部单元测试：corelib 211 项、avatar-orchestrator 586 项，失败 0。新增回归覆盖姿态超时禁止绕过门控、起立中暂停恢复、攻辩跨轮计时器清理、手动结束发言取消旧音频。

## 模拟器实测

设备：`emulator-5554 / Medium_Phone`，x86_64；实际窗口横屏 2400×1080。APK：`app/build/outputs/apk/debug/AIAvatar-v1.3-debug.apk`。

第一轮完整短赛程已经跑至 FINISHED，经过七个阶段，九个角色全部参与坐站；由这一轮发现攻辩跨轮计时器问题并修复。规则和控制修复后的构建再次跑完七个阶段，结束状态 FINISHED、lastError=null。之后仅调整单人镜头的头胸取景，已单独复核主持人坐姿、站姿发言及指定辩手镜头。导出 23 条记录（含一次暂停记录），其中完整播放 5 条、按时限或暂停打断 18 条、失败 0 条；四轮攻辩八次问答均有记录。短赛程刻意使用长稿与短限时，TIMEOUT/INTERRUPTED 是预期的硬截止结果。

## 当前边界

- 按本轮决定没有椅子，因此画面仍是无椅坐姿；本轮不宣称通过原方案的座面承托验收。
- 当前麦克风跟随手骨，尚无独立持麦臂约束；普通交流手势会让麦克风随手移动，不能将此视为“稳定举麦至嘴边”已经验收。
- 本轮运行固定稿短赛程，没有运行 31 分钟正式时长或真实 LLM 全场；也未覆盖九个不同重模型、断网、进程死亡后的持久化恢复。三个共享模型的模拟器结果不能替代这些项目的验收。
